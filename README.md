# 元素局 · 多人化学扑克牌

2—6 人联网房间。一名房主创建，朋友通过房间码或链接加入；全部准备后开始。保留一人对两位电脑的本机练习。

## 本次重做

- 服务器维护房间与完整牌局，D1 持久化；每位玩家只获取自己的手牌。
- 所有出牌在服务端重新校验回合、手牌、质量与有机物连接关系。
- 乐观并发控制防止同时提交和重复请求导致重复出牌；刷新、断线后可凭本机保存的入座凭证返回。
- 316 种内置物质，补充 KSCN、硫氰酸盐、硫代硫酸盐、配合物、水合物、开链葡萄糖和果糖等。
- 规范化学式保留数据中的常用写法；匹配用的原子计数不再用于生成无机物显示式。未成物质的原子组显示为“元素 × 数量”。水合物的前置系数不作下标。
- 未收录的物质可附资料提交，经全体玩家确认后加入当前房间，明确标记为房间约定，不冒充自动化学认证。
- 新牌桌、元素叠牌与数量加减、实时匹配、手机布局。
- 真正的单原子自由画布：拖动、单/双/三键、擦键、撤销重做、自动补氢；完整结构图同构验证接受等价画法。

## 本地运行

需要 Node.js 24（本地开发使用内置 SQLite），npm。

```sh
npm install
npm run build
npm run dev
```

打开 http://127.0.0.1:4173。`scripts/dev.mjs` 使用与云端相同的 Worker 和 API；数据库保存在忽略提交的 `.sites-runtime/rooms.sqlite`。在两个独立浏览器或无痕窗口中可测试双方交互。

## 发布结构

- `dist/` 顶层文件：浏览器源码。
- `server/worker.mjs`：房间与对局 API；静态资产打包嵌入 Worker。
- `dist/server/index.js`：由构建生成，未纳入源码提交。
- `.openai/hosting.json`：Sites 项目及逻辑 D1 绑定 `DB`。
- `db/schema.ts` / `drizzle/`：数据库结构和生成迁移。生产环境由发布流程应用迁移，不在请求中创建表。

## 验证

```sh
npm test
```

`tests/engine.test.mjs`：公式解析、精确质量、守恒、随机牌库和 72 局模拟。
`tests/multiplayer.test.mjs`：2—6 人、私有手牌、角色权限、并发重复出牌拒绝、服务端结构校验、共同收录与返回等候室。
`tests/browser.test.mjs`：两个独立浏览器身份走完整建房/加入/准备/有机物出牌/同步/刷新重连/投票/B 模式流程。运行前启动本地服务，并设置 `PLAYWRIGHT_MODULE`（playwright-core/index.mjs）和 `CHROMIUM_PATH`。

## 明确边界

有机物不区分立体异构；默认图鉴中的有机物需要结构校验。房间自行批准的物质只按配方校验，并在提交时向所有人说明。
网络暂断不自动托管出牌；当前玩家恢复连接后继续。房主可明确结束本局并回到等候室。
内置库不是全部已知化合物，房间共同确认是扩展机制，不是科学检索认证。
物质配比和电脑策略仍是可调整的游戏参数。B 的规则不数学保证有限回合结束；保留两圈重置，不额外强制结算。

原子量参考 CIAAW；KSCN 可核对 PubChem CID 516872：https://pubchem.ncbi.nlm.nih.gov/compound/516872。
